**Implementation requirements:**

4. Bound parser work and release resources on success, error, timeout and disconnect. A Promise.race alone does not stop CPU parsing. Use parser cancellation where effective; if necessary use a terminable worker thread with a narrow message contract. Document actual upload/extraction deadlines, page/text/resource limits and unavoidable constraints. Fail explicitly if supported extraction bounds are exceeded; a large upload with modest text must still pass. Avoid dependency/bundling surprises in the production build. No external network access during PDF parsing, no execution of embedded actions or fetching embedded URLs.

Do not save original uploads permanently; remove any owned temporary files and close parser/worker resources. Errors must release admission.
