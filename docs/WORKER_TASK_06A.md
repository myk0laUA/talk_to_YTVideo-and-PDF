**Requirements:**

Key uses normalized videoId, normalized requested language preference (explicit documented distinction between unspecified and chosen language), and native mode. Keep selected language and actual originating provider separate. Preserve full text, every ordered segment/stable reconstruction, fractional seconds and metadata needed to reconstruct the existing DTO. 2. Revalidate cached data with existing strict transcript/source boundaries before using it. Expired, empty, malformed, inconsistent or unknown-provider cache rows never mark a source ready; treat unusable data as a miss without serving partial text. Use a documented finite TTL (24hours is a reasonable starting value); cache reads do not renew expiry. Preserve original provenance on a cache hit; never relabel Supadata captions as direct extraction.
3. Each authorized import, including a cache hit, creates a fresh genuine Source UUID with the requesting visitor's owner/expiry and uses the existing atomic replacement transaction. Cache TTL does not extend visitor lifetime. Bootstrap/origin/admission/expiry checks occur before cache or provider work; a cache hit cannot bypass authorization or the current request limits.
4. On a miss call the one explicitly configured adapter once; validate success, upsert the cache with the existing unique key, then use the normal Source creation path. Preserve the prior source on provider/validation/cache-storage/source-storage failure. No provider calls inside database transactions. Bound DB waits; no automatic retries or fresh extraction after a cache hit merely because Source persistence failed. Define cache IO failures as authored storage-unavailable rather than silently making an extra upstream call. Partial public-cache population after a Source write failure is acceptable if it contains only validated public data and is documented.
