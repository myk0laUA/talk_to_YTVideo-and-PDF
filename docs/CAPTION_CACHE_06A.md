## Cache policy and boundaries

- Key: canonical eleven-character `videoId`, lowercased **requested** language preference, `mode="native"`. An omitted preference is `""`, distinct from explicitly requesting `"en"`. Empty/invalid explicit language is rejected. Preserve the requested language's original casing when calling the existing adapter; key equality is case-insensitive. Selected language remains separate and, for an explicit preference, must match case-insensitively; no language fallback is introduced.
- Store only the validated public native-caption success projection: generic title, full untrimmed text, every ordered segment with stable `segment-N` IDs and fractional seconds, exact counts, selected language, originating provider and versioned metadata containing only optional `trackType="automatic"`. No owner, cookie, private PDF, token, credential, upstream response/error or job data is written. Existing public URL adapters omit cookies/credentials; this cache introduces no authenticated/private extraction route.
- TTL is **24 hours from the successful miss/write attempt**. Reads never write or renew it. Cache expiry is checked after the database read await against current time. Expired, empty, wrong-key/mode, malformed timing/IDs, inconsistent fullText/counts/language, unknown metadata version/type or unknown provider rows are complete misses. Rows are not partially salvaged or eagerly deleted. The existing strict transcript validator runs on read and write; the ordinary caption Source validation/replacement/DTO boundaries still run for each import.
- Original provenance survives a hit, including a Supadata result under an application configured to use direct extraction on misses. `YOUTUBE_INGESTION_PROVIDER` selects the **miss** adapter. A hit is never evidence of that adapter's availability. The generic title is reconstructed deliberately; video titles are not fetched.
- Gate/configuration, exact origin/fetch metadata, signed visitor bootstrap/expiry, request bounds and shared process admission run before cache/provider work. Each hit/miss creates a fresh genuine Source UUID owned by the requesting visitor with that visitor's existing expiry. Deleting/replacing a Source does not touch the public cache or another visitor. Cache TTL never extends visitor lifetime.
- A miss calls the single configured adapter once, validates identity/language/provider, upserts the cache, then invokes the unchanged atomic Source replacement. No provider work occurs inside database transactions. Cache IO failure is authored `503/storage_unavailable`; it never triggers extraction after a read error or silently ignores a failed write. Prior Source is preserved on provider/validation/cache/source transaction failure. A validated public cache row may remain after a Source write failure; a subsequent authorized import can reuse it. A failed Source write after a hit never initiates fresh extraction.
- Cache read/write each use Prisma `maxWait=2000ms`, `timeout=5000ms`, ReadCommitted, PostgreSQL local `lock_timeout=1500ms` and `statement_timeout=3000ms`. The existing pool bounds connection acquisition. No application retry, request coalescing, fallback, cooldown, quota increase or automatic cleanup is added. Unique upsert uses the existing `(videoId, languagePreference, mode)` index. Existing Source-slot conflict/no-retry behavior is unchanged. Synthetic transactions do **not** prove SQL scheduling or native upsert races.
