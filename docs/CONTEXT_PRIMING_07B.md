## Encoding and budget boundary

`src/shared/priming-manifest.ts` projects a selected 07A variant to a deterministic immutable manifest. The caller supplies a unique run ID and voice/text mode. Instructions remain separate session configuration; every source payload is user-role JSON data. Hostile role labels, delimiters and commands remain text. The versioned grounding behavior stays the same between A and B; a short transport reconstruction rule and distinct loading/complete phase sentences are added separately.

A preserves the original plain fullText, including all separators, with source identity and UTF-16 offsets. It does not invent page/timestamp metadata absent from 07A's plain variant. B preserves the original section IDs, page numbers, caption start/duration fractions, empty PDF pages and section order. Neither sorts captions or normalizes text. B reconstructs each section by concatenating ordered fragment texts, then joins sections with the source separator. A concatenates fragment texts directly. No source text is duplicated; repeated identity/reconstruction fields are intentional framing. Tests compare all decoded text with the actual 07A fixtures, and every B locator with the prepared sections.

Large semantic text is split **before** encoding. Each event remains complete valid protocol JSON with `sectionIndex`, `sectionCount`, `part`, `offset`, `last`, locator and source metadata. A surrogate pair is not cut between fragments; lone surrogate code units still round-trip through JSON escaping. Empty sections produce an explicit empty fragment. Item IDs and predecessor order depend only on the supplied run and source order.

Application limits are 16,384 UTF-8 bytes per outbound event, 4,096 source items and 8,000,000 bytes for the whole representation. Callers may reduce the event bound to 2,048 bytes or more for later negotiated transports. These are memory/transport guards, **not model capacities or provider guarantees**. Oversize fails without a partial returned manifest, truncation or source writes. Incoming parsed events are capped at 24,576 serialized UTF-8 bytes; no inbound event queue is retained.

`manifest.representation` is the exact ordered `JSON.stringify` of initial update, each complete source event, and final update, separated by newlines. Each event is sent separately, without those separator newlines. `manifest.bytes` includes the separating bytes. This conservative measurement representation includes both configuration messages, repeated metadata, IDs, double JSON escaping and protocol framing; it is not the old 07A envelope or a statement about how the provider charges/retains tokens. Later real measurement must use this exact representation and explicitly account for model framing/history/output. Effective source context retains one copy; the instructions are updated by the final session configuration.

`priming-admission.ts` checks both selected prepared-budget `measured_fit` and independently supplied exact-wire `measured_fit`, verified token units/binding, positive measured counts, safe integer accounting, serialization adjustment, matching model/tokenizer/policy/capacity/reserves, exact representation and fit. Missing, malformed, negative, fractional, overflow, unverified, synthetic and over-budget inputs fail closed. There is no default capacity, tokenizer package or guessed tokens-per-character rule. `preparePrimingInput` returns only the manifest and copied budget evidence after those checks. It accepts a trusted prepared service result; it does not perform ownership verification.

This is a structural admission contract, not a cryptographic attestation or authorization boundary. A later **server** issuance flow must freshly authorize source ownership/expiry and supply genuinely reviewed token measurement. Directly manufacturing verified-shaped objects does not establish that measurement. The corresponding unit check tests validation arithmetic only and never starts a production controller with those objects. Real token capacities and accounting remain **NOT_RUN**.

The default `PrimingController` rejects offline/synthetic inputs. The only synthetic adapter is a subclass in `tests/priming/harness.ts` overriding its protected admission seam for explicitly synthetic fixtures. It always reports `basis: synthetic-test-only`; there is no environment flag, runtime synthetic factory or production route importing it. Every status, even with verified budget shape, has `productionReady: false`. `protocolReady` describes the acknowledgment gate only.

## Lifecycle and adapter obligations

1. Instantiate a controller with an injected clock, synchronous status observer, bounded synchronous primed callback, and optional fixed setup timeout (default 25 seconds; at most 120 seconds). Call `start({runId, connectionId}, input, transport)` with a **fresh, exclusive** transport. The adapter provides `isOpen/send/close/subscribe`; it parses complete incoming events and its disposer removes all owned listeners. The controller acquires no sockets, peers, keys, microphone, playback element or persistent storage.
2. `configuring`: send truncation disabled, no tools, text output and null turn detection. Wait for effective `session.updated`; validate session identity/model, instructions, truncation, tools, modality and turn detection. Only then enter `priming` and send source items in deterministic predecessor order. The injected send implementation must preserve invocation order.
3. Count only expected sent IDs with exact full text and completed `conversation.item.done`; `item.added` never counts, even when marked completed. Valid in-progress added events are accepted without progress. Reversed done events and duplicates are safe; unrelated items/errors naming another run are ignored. Relevant errors, source deletion/truncation, malformed acknowledgments, premature response creation or effective-setting mismatches fail closed.
4. After all done events and successful send completions, serialize one final session update. Voice selects audio output and Server VAD with response/interruption enabled and idle timeout null; text retains text output and null turn detection. Both modes change only the authored loading sentence to complete. This makes the two effective configurations distinguishable even in text mode. Duplicate initial settings cannot acknowledge the final phase; required-field comparison ignores unrelated server defaults/property order. Validate the final effective configuration before calling primed exactly once.
5. `canSendQuestions` remains false through both configuration phases and source ACKs. There is no question queue, arbitrary-send method or `response.create` path in this module. Future wiring must route questions only after this callback and keep any microphone upstream disabled until readiness. That wiring is outside 07B. Source delivery alone does not request a model response.
6. The deadline is fixed from `start`; duplicate events and slow sends cannot extend it, including a pending final send whose ACK arrived. Send throws/rejections, closed channels, timeout, relevant provider errors and context overflow produce authored safe categories, no retry, and one cleanup/close. Provider messages and source bodies are never logged or copied into status. The caller's preview/prepared source remains external and unchanged.
7. `stop()` cancels every active phase and is idempotent. Replacement calls Stop, then starts a new run on a new connection; no pending source, ACKs, questions or late events survive. Repeating Start with the same active identity **and transport object** is idempotent; a different active request is rejected without taking ownership of its candidate transport. Used run/connection IDs are rejected, with at most 128 runs retained per controller. At protocol readiness, source payloads/ACK sets and setup timer are dropped; the listener remains owned to detect transport/provider failure until Stop. Terminal cleanup disposes it and closes once. Rejected candidate transports remain the caller's responsibility.
