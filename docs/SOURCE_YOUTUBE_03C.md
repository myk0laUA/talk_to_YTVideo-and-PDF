## API and configuration

`POST /api/sources/youtube` accepts JSON `{ "video": "<YouTube HTTPS URL or 11-character ID>", "language": "en" }`. Language is optional. Input uses the existing host/ID/language validation; extra fields, provider/key overrides, arbitrary hosts, non-JSON and bodies beyond 512 bytes / 2 seconds are rejected. Declared and streamed sizes are checked. Mutations require exact Origin and same-origin fetch metadata (or absent metadata).

The first request without a valid signed visitor returns 401 `visitor_required` and a signed HttpOnly/SameSite=Strict cookie (Secure on HTTPS). A caller may retry **once** with that cookie. No body read, provider work, source mutation or admission charge occurs during bootstrap. An expired/forged cookie follows this same flow. Cookie and source expiry are never renewed by import/read/delete.

| Server setting | Behavior |
|---|---|
| `YOUTUBE_INGESTION_ENABLED` | Only literal `true` enables import; default off |
| `YOUTUBE_INGESTION_PROVIDER` | Required explicit `direct` or `supadata`; no automatic selection/fallback |
| `YOUTUBE_INGESTION_LOCAL_HTTP` | Literal `true` permits localhost/127.0.0.1 HTTP in a production local trial; all other hosts require HTTPS |
| `SUPADATA_API_KEY` | Required server-only for Supadata; unused by direct |
| `DATABASE_URL`, `APP_ORIGIN`, `VISITOR_COOKIE_SECRET` | Existing validated PostgreSQL/origin/signing configuration required; public-secret settings fail closed |

`GET /api/sources/:id` and `DELETE /api/sources/:id` support both genuine kinds when **either** PDF or YouTube ingestion is fully configured. An enabled PDF configuration allows reading/removing stored YouTube sources even if YouTube import is disabled, and conversely. Both configurations unavailable closes read/delete with 503. Read configuration returns only origin/secure/signing fields internally, never adapter keys. Disabling import alone does not revoke already stored sources while the other source path is enabled. Missing/foreign/expired/nonready/proof records retain the same 404 `unavailable` response. Expired/absent visitor cookies retain the 401 handshake. Reads reject foreign Origin/fetch metadata too.

Success is 201 with explicit metadata and a new committed UUID; owned GET adds full content. All authored responses are `no-store`/`nosniff`. PDF DTO fields are unchanged. Shared types now discriminate `PDF` from `YOUTUBE`; the PDF UI explicitly narrows its responses and remains PDF-only. YouTube metadata includes honest generic title `YouTube captions`, `videoId`, canonical watch URL, actual provider, selected language, optional verified automatic-track flag, segment/character/word counts and expiry. Content adds `fullText` and ordered `sections` with stable index-derived `segment-1`… IDs, text, start/duration **in seconds**. Fractional timing, zero duration, order, whitespace and every validated segment survive; no sorting/truncation/metadata service is introduced. IDs remain stable for an unchanged ordered transcript; they are not cross-revision identifiers.

Adapter output is checked again at the source boundary; persisted JSON is independently checked on read and on transaction output. PDF pages retain their existing array format. YouTube uses a JSON envelope with video ID, optional track type and segment array; the existing language column stores the selected language. Public DTO mapping explicitly copies checked fields, excluding DB rows, owner/slot hashes, keys, arbitrary JSON and provider jobs/config. Malformed stored content returns authored storage-unavailable; no partial content is returned.

Supadata still requests `mode=native&text=false`; direct uses existing caption tracks. Neither path generates audio transcription. Forced provider failures return fixed authored codes/messages; upstream bodies/messages are discarded. No request retries or alternative adapter are added (existing bounded Supadata job polling is unchanged).

## Atomic storage and forward migration

`activeSourceOwner` is the single Prisma ownership slot, mapped to the **existing** SQL column `uploadedPdfOwner` and unique index `Source_uploadedPdfOwner_key`. There is no second per-kind slot. Genuine PDF/YouTube rows occupy it; synthetic proof records leave it NULL. The repository deletes only a matching genuine owned slot and creates its replacement inside one bounded transaction. Provider work and body reads happen before the transaction. Transaction bounds remain lock 1500 ms, statement 3000 ms, maxWait 2000 ms, timeout 5000 ms, ReadCommitted. P2002/P2034 produce 409 `replacement_conflict`, with no retry. The unique index is the cross-process invariant; process-local admission is not relied on for correctness.

Migration `prisma/migrations/20261018200000_active_source_owner/migration.sql` atomically replaces the old PDF-only CHECK with `Source_active_source_identity`. PDF branch is equivalent to the previous constraint. Every NULL-slot row stays valid. YouTube slots require matching owner, READY, a known provider, canonical video URL, valid non-NULL language and NULL pageCount. Existing column, unique index, UUIDs, payloads and expiries are retained; no backfill, deletion or data rewrite. JSON/content validation remains application responsibility.
