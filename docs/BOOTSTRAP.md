## Implementation choices

- Manual Next scaffold in the existing repository avoids overwriting the handoff or reinitializing Git. App Router server components and plain CSS suffice for the current static shell. No parser, OpenAI, transcript provider, authentication or animation dependencies yet.
- UI lives in `src/app`; private infrastructure in `src/server`; public metadata in `src/shared`. `server-only` guards environment and database runtime modules. Nothing serializes environment or database records into the page.
- `.env.example` has empty credential values. Shell/build/test/generation work without services. Only database access requires `DATABASE_URL`; configured malformed URLs and known public-secret variables fail with redacted messages. No `.env` with real credentials was created or read.
- Prisma 7 uses `prisma.config.ts`, the `prisma-client` generator and `@prisma/adapter-pg`. The lazy server client bounds its pool to five connections and connection acquisition to five seconds. This is infrastructure, not implemented access control.
- Initial schema includes temporary `Source` and public `TranscriptCache`, owner hash and expiry indexes, normalized content/sections and provider metadata. Cache uniqueness is video/language-preference/mode. UUIDs are generated by Prisma. No database TTL policy, cleanup job, visitor cookie, owned-source service or conversation history is implemented.
- SQL was generated **offline**, with `npx prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script --output prisma/migrations/20261018031000_initial/migration.sql`. It has not been applied. Prisma 7.10.1's engine required a datasource configuration even for this offline diff: omitting it exited zero without SQL; the fixed config supplies an empty URL when unset. No invented connection string is used.
- npm's version-pinned install-script allowlist covers Prisma, its engine and the resolver's required setup. Clean install generated the client successfully. No blanket script approval or global package install was used.
- `next dev` initially appended framework guidance to `AGENTS.md`. Set documented `agentRules: false` to retain the hand-maintained instructions, which point to bundled version-matched Next docs.
- Selected skills are vendored at project scope. Preserve `skills-lock.json`; see `SKILLS.md` for exact installed identities and manual hook activation. `PRODUCT.md`/`DESIGN.md` summarize the supplied brief and minimal shell, not a completed Step 05 design.

## Known tooling issue

`eslint-config-next` → `@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces` is affected by [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), stack exhaustion from deeply nested patterns. `npm view braces version` returned 3.0.3, the affected latest release. npm suggested downgrading `eslint-config-next` to 14.2.35, which does not match the application. No forced downgrade, override or audit suppression was added. These packages are development lint tooling; production-only audit is clear. PM should track upstream remediation and the ESLint 9 support notice.
