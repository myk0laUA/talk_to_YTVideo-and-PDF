## Implementation and ownership

`src/app/text-session.tsx` composes the accepted10A `TextLifecycle` and09B `TranscriptView`. An application-supplied factory is an ownership interface, never an admission flag. Production supplies **no factory**: its Start/Stop/Send/composer remain disabled and an explicit unavailable message accompanies the unchanged disabled voice/text entry controls. There is no production transport, test route, query activation, positive admission subclass or authored answer.

The keyed React owner creates one controller in componentDidMount, with no eager Start. Before unmount it detaches its observer, drops the pending draft reference and disposes the controller. StrictMode disposes the replayed mount before creating its replacement. A source identity change/removal synchronously replaces the owner, draft, transcript, receipt and presentation key before paint. Each explicit Start reuses its owner's controller with a new session identity and empty history/draft. Stop preserves received text. No storage/URL writes, event listeners, credential calls or connection code were added to the UI. The existing transcript alone owns its passive scroll listener and Jump behavior.

Enter and Shift+Enter insert newlines; Send question is the sole submit action. Composition start/end guards prevent even a Send click from submitting during composition. The coordinator's synchronous canSubmit gate rejects duplicate clicks and in-flight sends. The composer is read-only during connection, checks, sending and generation (focus remains available); Send is disabled until ready. Unicode/whitespace is passed unchanged. Empty/whitespace and >1,000 UTF-16-code-unit questions receive inline explanations; no maxlength or truncation hides an overlimit value. The UI explains that some symbols use multiple units.

Draft clearing follows the actual coordinator transcript: only a **new**, finalized user item containing this exact question confirms receipt. Older identical questions cannot clear a new draft. Submission acceptance, item.added, local write settlement and finalized receipt are distinct. Final receipt can clear the draft while the local write is pending; the UI then says the question was received but the send is finishing. Only10A's settled write + final ACK barrier can request an answer. Uncertain sends keep their draft; there is no retransmission. Fresh Start explicitly explains that conversation/draft will be cleared. Partial output remains honestly unfinished on Stop/error/timeout.

Statuses name connection, source loading, ready, question checks, sending without receipt, receipt/waiting, arriving answer, ended, failed and unavailable. Failure copy omits raw provider errors. Status announcements change by phase; transcript announcements retain09B's summary policy, with no token-by-token live text. Length counters are outside live regions. Labels, native buttons, existing focus outlines/48px targets, wrapping, page scroll and reduced-motion behavior preserve the existing design.
