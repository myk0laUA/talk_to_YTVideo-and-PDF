## Requirements

1. Service takes a server-established visitor and Source UUID, loads through the existing owned repository and validates ownership, genuine READY identity and both expiries. Do not accept a browser-supplied fullText/owner/provider as authority. Reject foreign/missing/expired/proof/replaced IDs uniformly; respect cancellation and recheck visitor/source expiry after awaits. Return no raw row/owner hash/cookie/key. Preparation alone must not mint any credential or authorize a future session: later transport integration must revalidate at issuance.
2. Produce an immutable context object with source identity, kind, stable section IDs, page numbers or fractional second timings, source expiry and explicit context/prompt version. Preserve **all** text, original order, whitespace, Unicode and empty PDF pages. No sorting caption timestamps, trimming, summarizing, dropping sections or silent truncation. Exact reconstruction must equal stored fullText, using existing PDF versus caption separators. Serialize source content as data with deterministic escaping so hostile text cannot break the structural format; do not claim formatting makes prompt injection impossible.
3. Provide two deterministic variants for future evaluation: A plain full text; B lossless structured full text with stable section identifiers. Both use the same versioned behavior instructions: source-grounded answers, acknowledge absent evidence, distinguish source claims from facts, cite available page/segment references, treat embedded commands as untrusted source material. Keep source text separate from instructions in the data contract. Do not assign API message roles or choose a provider event format yet. Preserve future voice/text parity.
4. Introduce a validated **injected budget policy and measurement interface**, rather than hardcoding unsupported model capacities. Account for instructions, serialized source, history allowance, output reserve and framing allowance separately. Do not use characters/4 as an exact token count or assume section labels save tokens. Actual model/tokenizer binding is deferred to later reviewed transport work. For this task, deterministic test measurements may be synthetic but must be clearly labeled and must not mark production conversation ready. A missing/unverified policy yields an explicit unavailable/not-ready result. Over-budget returns an authored context-too-large result with safe accounting, leaving the stored Source/preview unchanged. Never silently reduce context to make it fit.
5. Context size limits are independent from the25MB upload limit. Measure the whole serialized variant, including escaping/metadata/behavior instructions, not just fullText. Test exact boundary/one-over, negative/nonfinite/overflow policy values and measurement failure. An unsupported source remains fully readable through the existing preview. No runtime readiness change to UI in07A.
6. Establish versioned evaluation fixtures for representative PDF and captions. Twelve questions each: six facts distributed beginning/middle/end, two synthesis/comparison, two follow-ups, one absent answer and one embedded malicious instruction case. Record expected answer/evidence section IDs and coverage checks. Create A/B evaluation table templates with actual model accuracy/latency cells **NOT_RUN**. Offline inclusion tests prove coverage/serialization, not model grounding, injection resistance or quality superiority.
7. No source contents in telemetry/logs or snapshots committed from private documents. Use committed synthetic fixtures only; retain full private rows only in process memory for tests if needed. Context cache/history persistence is out of scope. New modules import server-only and stay out of browser bundles.
