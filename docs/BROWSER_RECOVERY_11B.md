## Behavior and ownership

`src/app/browser-session.ts` creates one set of four window listeners for the mounted voice or text owner. Construction occurs in `componentDidMount`, with matching removal before controller disposal in `componentWillUnmount`. The module does not read browser APIs during evaluation or rendering. StrictMode mounts and source/mode replacement get separate helpers; disposed callbacks return without touching their former owner. No new timer, polling or reconnect loop is used.

Both persisted and non-persisted `pagehide` synchronously call the actual coordinator's `stop()`. Its existing attempt invalidation, cancellation, timer/listener cleanup and once-only resource release run before the handler returns. Partial transcript text remains in the surviving document. The departure latch blocks actions until `pageshow`; restoring the page clears only this latch. It never starts a session. React unmount continues to dispose the controller and erase its in-memory transcript. A full reload has no history guarantee. `visibilitychange` is deliberately not a shutdown event in this task.

The explicit product policy stops conversation work when `navigator.onLine` reports false. This browser hint does not prove provider reachability or diagnose network loss. Start, Send, unmute/interruption and playback handlers check the helper synchronously, including a click before the offline event/React update is delivered. Offline text stays read-only with the unconfirmed draft intact; mode selection, source reading and transcript inspection remain available. Returning online only explains the browser report. A deliberate new Start clears the former history/draft under the accepted 10C policy and runs preparation, admission and full source ACK barriers again. It does not retransmit a question.

Adapter closure remains authoritative while the browser reports online. The existing voice lifecycle classifies transport closure as connection failure. Text now preserves the same category when the priming controller reports transport failure, including during setup. Provider/setup failures keep their own wording; no failure is asserted to prove network loss. Budget refusals and unavailable production presentation remain closed regardless of connectivity. This adds no positive admission or production factory.

Visible copy distinguishes ordinary Stop, page departure, browser offline/online and connection failure. The existing polite status regions describe state and recovery; disabled actions and the text field reference that guidance. No automatic focus movement is added. Existing transcript rendering, reading-anchor behavior and fresh-history mode switching are retained. No CSS or source-import changes are made.

## Browser semantics consulted

Fetched **19 October 2026 UTC / 18 October Toronto**:

- [MDN pagehide](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagehide_event): departure event and persisted flag; BFCache compatible, but not guaranteed for mobile process termination. This task follows its explicit no-visibilitychange-shutdown policy.
- [MDN pageshow](https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event): initial load, history navigation and frozen/BFCache restores; it is not a Start action.
- [MDN navigator.onLine](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine): heuristic browser/OS signal that cannot prove internet/provider reachability. The brief explicitly chooses conservative conversation shutdown despite that limitation.
- [Chrome/web.dev BFCache](https://web.dev/articles/bfcache): distinguish pageshow.persisted from a reload; pagehide persistence eligibility is not proof of actual restoration.
- [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md): focused status/focus/forms/reflow review with selected local Impeccable harden/clarify, React and Playwright guidance. Existing design preserved; generic suggestions do not expand scope. No Next framework change required a new framework API.
