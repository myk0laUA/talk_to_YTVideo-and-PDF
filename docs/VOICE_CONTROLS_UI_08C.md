## Ownership and presentation

`src/app/voice-session.tsx` exports `VoiceSession` and a typed controller factory. The factory transfers one actual `VoiceLifecycle` to a mounted owner; it does not verify budgets. Keep the factory stable for the lifetime of that owner. A source ID key creates a new owner when the source changes or is removed. Mount creates the coordinator only; Start, playback and retry always require explicit actions. Unmount detaches the observer before disposing its controller. React StrictMode's mount/dispose/remount creates separate, once-disposed instances and never opens a connection eagerly.

The component calls only `start`, `mute`, `unmute`, `stop`, `playAudio` and `interruptCurrentResponse`. It does not send protocol commands. Stop preserves the actual stopped transcript, including unfinished text. Deliberate Start clears the controller transcript and changes the view key. Source removal/replacement and unmount discard the old view before paint and dispose the coordinator. Nothing is saved to storage or the URL. No factory is passed by production; the existing disabled Start Voice Chat entry and 10B text UI remain unchanged. The new component is available for future composition without redundant public controls.

Microphone and speaker playback have independent visible descriptions and accessible status announcements. Microphone failure cannot distinguish denial from unavailability or timeout in 08A, so the copy names all three possibilities. It explains permission recovery and that text mode is a separate next step; no working-looking mode switch appears. Ended microphone tracks have a distinct message. Playback is enabled through a separate explicit action. A blocked or timed-out play operation offers Try speaker playback; it never reacquires the microphone. Stop is enabled throughout connection/source/microphone/playback/interruption waits.

Response feedback distinguishes generation from output streaming/stopped/cleared/unknown, speech activity, and pending/confirmed/failed interruption. It projects 08B's result, including the settled-write plus generation/buffer confirmation barriers. Generation completion does not change playback or imply the answer was heard. A failed interruption directs the visitor to Stop and is not retried automatically. The UI also disables interruption for uncertain ownership of the output buffer and capacity failure; the coordinator remains the authoritative duplicate/correlation guard.

09B `TranscriptView` is reused without changes. The turn list is not a live region. Voice announcements depend on lifecycle facts rather than transcript tokens. Streaming keeps current focus and the earlier reading anchor; keyboard Jump to latest is explicit. Native controls, existing focus rules, at least 48px targets and scoped wrapping use the established design. There is no waveform, audio level or added animation. Root 200% text and CSS 200% layout zoom are emulated checks, not browser-toolbar zoom or phone evidence.
