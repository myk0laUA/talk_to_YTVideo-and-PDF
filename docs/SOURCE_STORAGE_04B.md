## Public contract

All three handlers require `PDF_INGESTION_ENABLED=true`, valid private `VISITOR_COOKIE_SECRET`, exact `APP_ORIGIN`, and valid server-only `DATABASE_URL`. The gate defaults off independently of `PDF_PROOF_ENABLED`. Production origin requires HTTPS; only an explicitly opted-in loopback build permits `PDF_INGESTION_LOCAL_HTTP=true`. No mock selector, alternate repository URL or test endpoint exists in application configuration/requests.

| Route | Success | Behavior |
| --- | --- | --- |
| `POST /api/sources/pdf` | 201 `{ok:true,source:metadata}` | One bounded multipart `file`, accepted 04a ASCII `.pdf` filename/media grammar. Signed visitor checked before body consumption; extracts completely before transaction. |
| `GET /api/sources/{id}` | 200 `{ok:true,source:content}` | UUID v4; owner + uploaded slot + READY + PDF + real parser + expiry filter. Adds complete `fullText` and ordered `sections` to metadata. Does not refresh cookie or expiry. |
| `DELETE /api/sources/{id}` | 200 `{ok:true}` | Same ownership/discriminator/expiry predicates. Removes at most the named owned upload. Repeated deletion returns the same 404 as missing/foreign/expired IDs. |

Metadata fields are exactly `id`, `kind`, `title`, `parser`, `pageCount`, `characterCount`, `wordCount`, `warnings`, `expiresAt`. Title is `Uploaded PDF`; no filename persistence is introduced. Parser is `pdf-parse@2.4.5`. Content sections contain only `id`, `pageNumber`, `text`; JSON is checked and projected rather than passing arbitrary stored properties through. There is no `ownerSessionHash`, `uploadedPdfOwner`, environment, raw Prisma row, original PDF bytes or TranscriptCache write in public results.

All authored responses have `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. Errors use `{ok:false,error:{code,message}}`, reusing 04a PDF errors plus `unavailable` (404), `storage_unavailable` (503), and `replacement_conflict` (409). Internal messages/SQL/URLs/text are never interpolated. Missing/forged/expired visitor gets 401 and a fresh independent signed cookie; retry is required before upload. Losing a cookie cannot recover prior ownership. Late expiry during an operation returns 401; a subsequent request performs the fresh-cookie handshake.

POST/DELETE require exact Origin and absent or `same-origin` Sec-Fetch-Site. GET permits absent Origin for same-origin navigation, rejects foreign Origin and cross-site/same-site fetch metadata. Invalid/unknown/foreign/synthetic/expired source IDs all receive 404 `Source unavailable`, without existence/metadata/content details. Invalid IDs never reach the repository.

## Storage, transaction and lifecycle policy

Prepared migration: `prisma/migrations/20261018080000_uploaded_pdf_owner/migration.sql`. **NOT APPLIED**. It adds one nullable unique `Source.uploadedPdfOwner` column and a database CHECK: a non-null slot must equal `ownerSessionHash`, have PDF/READY state, real pinned parser identity and null canonical origin. Existing rows, including synthetic lighthouse and database-probe fixtures, keep NULL. Nullable uniqueness enforces at most one uploaded PDF row per owner across processes, including expired physical rows. The duplicated hash is private infrastructure, not an authorization input from the client. The CHECK is intentionally tied to the accepted parser; a future parser-version change must review it.

Successful replacement is a Read Committed Prisma interactive transaction: delete the previous row constrained by owner + slot + real uploaded identity; create a complete READY row with a fresh server UUID; verify liveness after each destructive/storage await. A unique slot makes that delete bounded to at most one row. Create failure, cancellation or expiry before the transaction callback succeeds rolls back the deletion. Other visitors and NULL-slot synthetic records are outside every replacement predicate. Deletion additionally rechecks the row expiry before and after its delete await. Reads recheck both visitor and returned source expiry after the transaction await.

Prisma transaction options are `maxWait:2000`, `timeout:5000`; transaction-local PostgreSQL `lock_timeout=1500ms`, `statement_timeout=3000ms`. Existing lazy pool has maximum five connections and a 5000ms connection timeout. These are component bounds, not a guaranteed HTTP round-trip duration. Installed Prisma 7.10.1 transaction signatures in `src/generated/prisma/internal/class.ts` and runtime types were consulted; Next 16.4.2 local route/dynamic-params guide was consulted for the Promise params handlers.

Concurrent completions may serialize successfully (last committed replacement wins), or one may fail a unique/write conflict (409) or bounded lock/statement timeout (503). A loser must never return its uncommitted UUID as success. The unique index is the database invariant; process-local parser admission is additional resource control. No automatic retry or idempotency key is implemented. An explicit upload retry extracts again and creates a new UUID if it succeeds. A response lost after commit leaves uncertain client outcome. Cancellation/expiry detected **after** commit suppresses success but cannot undo committed replacement/deletion; a prior upload may already be invalidated. A GET that overlaps replacement may return the previously valid snapshot; after replacement completes, a new GET of its old ID returns 404. No lease spanning delivery of a response is claimed.

Source expiry equals, and never exceeds, the validated visitor's current expiry (one-hour cookie policy). Reads never extend it. Expired physical rows remain inaccessible; the next successful same-owner replacement can remove its prior slot. No cleanup daemon is added. Original bytes remain in the existing bounded in-memory upload/worker flow; no uploaded file or application temporary file is written to disk.

Both production PDF upload and extraction diagnostic use `src/server/pdf/admission.ts`'s process-global Admission instance: one active upload/parse/storage operation per process, six attempts per visitor/hour, 20 shared-network/global/hour and 40 lifetime attempts. Capacity is released in `finally`, including parser/DB failures and disconnects. No client IP header is trusted; the existing conservative shared network bucket remains. Read/delete use bounded repository transactions. Distributed request admission and public traffic hardening remain later work.

The accepted 04a upload/parser limits are unchanged: 25,000,000 file bytes plus 16,384 framing bytes; 4096-byte multipart headers; 30-second upload and 15-second worker deadline; 500 pages/2,000,000 text code units. Normal proof/credential guards are unchanged and still accept only their deterministic synthetic lighthouse record.
