## Contract and authorization

`createContextService({ repository, now })` in `src/server/context/service.ts` accepts a **server-established** signed/validated Visitor, Source UUID, AbortSignal and optional injected policy/measurer. It accepts no caller text, provider selection or owner field as source authority. Use the existing `createSourceRepository` with an intended server database when later integrated; routine 07A tests use that actual repository over isolated synthetic storage only.

The service uses existing `requireLive`, `requireOwned` and `checkedSource` boundaries, verifies the returned UUID, genuine READY identity, active owner and both expiries, and checks cancellation/expiry after every awaited read/measurement. A final owned read rejects removal/replacement or changed content during measurement. Missing, foreign, expired, proof, nonready, removed and replaced IDs yield the same authored unavailable result. Invalid persisted structure is storage-unavailable. Failures include no source body or underlying exception text. Cancellation returns promptly even for a noncooperating read/measurer; abort listeners are removed and late rejections consumed. Underlying read-only work can finish, but cannot publish a result after cancellation.

No raw rows, owner hashes, cookie/token, provider keys or source provenance fields are returned. Context includes only source UUID/kind/expiry, version identifiers, complete text, separator and copied/frozen safe sections. This is a server-internal data contract, not a new browser DTO or public endpoint. All four new modules import `server-only`; none is wired into runtime routes or client code. Source and public cache writes, history persistence, provider calls and credential creation are absent.

Preparation always returns `conversationReady: false`, `providerConfirmed: false`, `issuanceRequiresRevalidation: true`, including when an injected measurement fits. `status: prepared` means only the immutable document was prepared. Inspect **each variant's** budget result. Future issuance must freshly reauthorize the visitor and Source, bind a reviewed tokenizer/model policy, account for the actual transport representation and wait for provider context acknowledgement before accepting questions. The final read does not prevent a later deletion or replacement after preparation returns.

## Lossless variants and budget policy

`source-context-v1` preserves every stored character and section in original order: PDF joins with two newlines, captions with one newline. Empty PDF pages remain sections. Caption order is never sorted; fractional/zero timing is unchanged. `source-grounding-v1` provides a shared immutable behavior array. A contains complete plain text with identity/expiry/separator; B contains complete sections with stable page/segment IDs and locators. B avoids duplicating fullText. JSON escaping round-trips control characters, quotes, delimiter-like/hostile content, Unicode and lone surrogates; `<`, `>`, `&`, U+2028/U+2029 are escaped. Formatting provides structure, not proof of prompt-injection resistance. No API roles, event formats, transport splitting or summarization are chosen.

Supply `BudgetPolicy { version, binding, capacity, historyAllowance, outputReserve, framingAllowance }` and a `ContextMeasurement { binding, measure }`. Model/tokenizer identities and verification/unit must match. No default capacity or characters/4 estimate exists. Positive capacity and nonnegative reserves must be safe integers; measurement counts for nonempty serialized components must be positive safe integers. Negative, fractional, nonfinite, overflowing, mismatched and unverified policies/measurements fail closed with `budget_unavailable`. Missing policy/measurer is also explicitly unavailable. Overflow arithmetic uses BigInt before returning safe numeric accounting.

Measure instructions, serialized source (metadata and escaping included), and the **complete serialized envelope** independently. Total = complete variant + history allowance + output reserve + framing allowance. Instructions/source counts are diagnostic components; `serializationAdjustment = completeVariant - instructions - serializedSource` records JSON framing and nonadditive tokenization. It can be negative. Do not sum diagnostic counts again. Framing allowance separately covers future provider framing; it is not a claim that the current JSON matches a provider event.

Synthetic bindings require `verification: synthetic`, `unit: synthetic-units`; a fit is `offline_fit`. Test measurement is exact UTF-8 **bytes**, not tokens. A reviewed future binding can use `verified`/`tokens` and return `measured_fit`; even this never marks provider/session readiness. No actual model is bound or verified by 07A. Over-budget yields `context_too_large` with safe accounting and authored copy. No text is removed; stored Source and existing full preview remain unchanged. Context limits are independent of the 25 MB PDF upload ceiling.
